# ТЗ: персональный ИИ-бот в Telegram Serverless

Версия: 0.2 (реализовано в коде; изменения против 0.1 отмечены «v0.2»)
Дата: 19.10.2026
Владелец: Артур

---

## 1. Цель

Один бот, который:
- принимает текстовые запросы и отвечает на них через ИИ-модель из ClaudeHub API;
- позволяет переключать модель;
- хранит память на нескольких уровнях;
- отвечает от моего имени в личных чатах и в группах, когда я его об этом попрошу;
- оформляет и публикует посты в моих Telegram-каналах, фото для постов присылаю боту сам.

Все ответы бота текстовые. Голосовых и графических ответов нет.

**Роль бота (v0.2).** Бот — личный помощник владельца, который «работает на проценте»: чем больше зарабатывает владелец, тем больше достаётся боту. В коде это рабочая рамка системного промпта: бот думает о деньгах, сроках и приоритетах владельца, считает выгоду и предлагает конкретные шаги, но помогает и во всём остальном (тексты, переписка, планирование, быт). «Процент» не должен искажать советы: бот не льстит, не подталкивает к вредным тратам, не предлагает обман и честно отделяет факты от догадок.

## 2. Платформа и стек

- **Хостинг:** Telegram Serverless (https://core.telegram.org/bots/serverless). Отдельный сервер, Cloudflare или Yandex Cloud не используются.
- **Язык:** JavaScript (ES-модули). Зависимостей из npm нет: доступны только SDK платформы и собственные модули.
- **Инструмент разработки:** CLI `tgcloud` (`npm create @tgcloud/bot`), тестирование через `npx tgcloud run`, деплой через `npx tgcloud push`, миграции через `npx tgcloud migrate`.
- **База данных:** встроенная SQLite платформы (через `db` из SDK).
- **ИИ:** ClaudeHub API, вызов через `fetch` из SDK.
- **Telegram:** Bot API через `api` из SDK.
- **Mini App:** для экрана настроек (модель, память, шаблоны постов). В MVP не обязателен, см. раздел 11.

## 3. Пользователи и доступ

- Бот работает для одного владельца. Владелец задаётся списком `OWNER_IDS` (Telegram `user_id`) в секретах платформы.
- Все остальные пользователи получают один ответ: «Этот бот приватный» и больше не получают ничего. Запрос сохраняется в журнал.
- **v0.2.** В группах работает трёхпозиционный переключатель режима (`/group`): **выкл** (молчит), **по запросу** (отвечает на упоминание, на ответ боту и на `/ask`), **на все** (отвечает на каждое сообщение). По умолчанию для группы, куда бота добавил владелец, — «по запросу». Если бота добавил не владелец, он сразу выходит из группы.

## 4. Функциональные требования

### 4.1 Ответы ИИ (личка с владельцем)

- **FR-1.** Текстовое сообщение владельца отправляется в ClaudeHub с учётом памяти (раздел 6) и текущей модели чата.
- **FR-2.** Ответ выводится по мере генерации (стриминг через редактирование сообщения), если ClaudeHub и Bot API это позволяют. Иначе ответ выводится целиком после генерации.
- **FR-3.** Ответ длиннее 4096 символов разбивается на части по границам абзацев.
- **FR-4.** Во время генерации показывается индикатор набора текста (`sendChatAction`).
- **FR-5.** При ошибке ClaudeHub (таймаут, 5xx, лимит) бот делает до 2 повторных попыток с паузой, затем пишет владельцу понятное сообщение с кнопкой «Повторить».

### 4.2 Переключение модели

- **FR-6.** Команда `/model` показывает список моделей с inline-кнопками. Текущая модель отмечена.
- **FR-7.** Выбор модели сохраняется отдельно для каждого чата (личка, каждая группа).
- **FR-8.** Список моделей берётся из ClaudeHub API и кешируется на 24 часа. Модели в коде не зашиваются.
- **FR-9.** Если выбранная модель недоступна, бот пишет об этом и предлагает выбрать другую. Тихой подмены модели нет.

### 4.3 Память

См. раздел 6.

- **FR-10.** Команды: `/memory` (показать, что бот помнит), `/remember <текст>` (сохранить факт), `/forget <номер или текст>` (удалить факт), `/forget_all` (очистить долговременную память, с подтверждением), `/reset` (очистить историю текущего чата, долговременная память не затрагивается).

### 4.4 Ответы от моего имени в личных чатах (Business)

- **FR-11.** Бот подключается к моему аккаунту через Telegram Business (нужен Telegram Premium).
- **FR-12.** Автоответ от моего имени включается только командой владельца для конкретного чата или по списку контактов. Глобального автоответа незнакомцам нет.
- **FR-13.** Перед первым ответом в каждом новом чате бот присылает мне черновик и ждёт подтверждения. После подтверждения режим для этого чата сохраняется.
- **FR-14.** Команда `/business off <чат>` отключает автоответ для чата. Команда `/business off all` отключает его полностью.
- **FR-15.** Каждый ответ от моего имени записывается в журнал: чат, текст, время, модель, режим (авто или после подтверждения).

### 4.5 Ответы в группах

- **FR-16 (v0.2).** Режим «по запросу»: бот отвечает на упоминание `@bot`, на реплику к своему сообщению и на `/ask`; остальные реплики только запоминает в контексте группы (без вызова ИИ). Режим «на все»: бот отвечает на каждое сообщение, но не чаще одного ответа за 4 секунды и не более 40 ответов в час на группу (прямое обращение паузу не ждёт). Режим «выкл»: молчит и ничего не сохраняет. Для режима «на все» у бота нужно отключить Group Privacy в BotFather.
- **FR-17.** Ответ в группе отправляется от бота, а не от моего имени. Если я попросил ответить от моего имени, это отдельная команда, и она доступна только владельцу.
- **FR-18.** Участникам группы бот не выполняет команды управления (`/model`, `/remember`, `/post`, `/business`, `/stop`). Режим группы владелец переключает командой `/group` (кнопки «Выкл / По запросу / На все»).
- **FR-19.** Ответ в группе можно отправлять как ephemeral-сообщение (видно только автору запроса), если владелец включил эту опцию для группы. Опция выключена по умолчанию.
- **FR-20.** В группе память отдельная. Личная долговременная память владельца в группе не используется, кроме случаев, когда владелец явно просит.

### 4.6 Посты в каналах

- **FR-21.** Владелец присылает боту фото и текст или описание (в одном сообщении или в двух). Команда `/post <канал>`, если канал не указан, бот спрашивает.
- **FR-22.** Бот составляет текст поста в стиле выбранного канала (см. раздел 6.4) и показывает черновик с кнопками: «Опубликовать», «Переделать», «Изменить вручную», «Отмена».
- **FR-23.** Публикация через `sendPhoto` с подписью до 1024 символов или через `sendMessage` без фото до 4096 символов. Форматирование: HTML.
- **FR-24.** Бот должен быть администратором канала с правом публикации. Если прав нет, бот пишет, какие права нужны.
- **FR-25.** Каждый черновик и каждая публикация сохраняются в таблицу `posts` (статус: черновик, опубликован, отменён, ошибка).
- **FR-26.** Переделка: кнопка «Переделать» принимает текст замечания («короче», «без эмодзи»), бот генерирует новую версию. Количество переделок не ограничено, но каждая сохраняется.
- **FR-27.** Фото сохраняется в `file_id` Telegram. Если фото нужно переиспользовать, повторная загрузка не требуется.
- **FR-28.** Отложенная публикация не входит в MVP (см. раздел 12, открытый вопрос).

### 4.7 Служебные команды

- **FR-29.** `/stop` немедленно отключает все ответы бота во всех чатах (включая Business и группы), кроме команды `/start`. `/resume` включает обратно.
- **FR-30.** `/usage` показывает расход токенов за сегодня и за месяц, остаток по лимиту.
- **FR-31.** `/start` и `/help` показывают список команд.
- **FR-32.** Меню команд регистрируется через `setMyCommands` и обновляется при деплое.

## 5. Сценарии использования

### 5.1 Обычный вопрос в личке
Владелец пишет текст → бот показывает индикатор → ответ выводится по частям → сообщение и ответ сохраняются в историю чата.

### 5.2 Смена модели
Владелец: `/model` → выбирает кнопку → бот подтверждает: «Модель: <название>. Следующий ответ от неё». Предыдущие ответы не меняются.

### 5.3 Ответ в группе
Участник пишет `@bot как настроить X` (в режиме «на все» — просто пишет) → бот отвечает в группе с учётом памяти группы → владелец получает копию в личку, если включено (FR-33).

- **FR-33.** Опция уведомлений: владелец получает в личку копию каждого ответа бота в группах (включается командой, выключено по умолчанию).

### 5.4 Ответ от моего имени (Business)
Новый собеседник пишет мне в Telegram → бот присылает мне черновик ответа с кнопками «Отправить от моего имени», «Изменить», «Не отвечать» → после подтверждения ответ уходит, режим для чата сохраняется → дальше по настройке.

### 5.5 Пост в канал
Владелец: фото + «анонс нового курса, цена 5000» → `/post Сейчас объясню` → бот присылает черновик с фото и текстом → «Переделать: короче» → «Опубликовать» → пост опубликован, ссылка на сообщение возвращается владельцу.

## 6. Память

Четыре уровня. Каждый уровень хранится отдельно, с привязкой к `chat_id`.

### 6.1 Уровень 1: последние сообщения
- Хранится последних N сообщений чата (по умолчанию N = 20, настраивается).
- Перед запросом в ClaudeHub история обрезается по бюджету токенов (по умолчанию 8000 токенов на историю, настраивается).
- Таблица `messages`: `id`, `chat_id`, `role`, `text`, `created_at`, `model`.

### 6.2 Уровень 2: сводка
- Когда история превышает N сообщений, старые сообщения сжимаются в сводку моделью.
- Сводка хранится в таблице `chats` (поле `summary`) и обновляется каждые 20 новых сообщений.
- Сводка подаётся в контекст перед последними сообщениями.

### 6.3 Уровень 3: долговременные факты
- Таблица `memories`: `id`, `scope` (`owner` или `group:<id>`), `text`, `source` (`explicit` или `confirmed`), `created_at`.
- Записи появляются по команде `/remember` или после подтверждения: бот может предложить сохранить факт, но не сохраняет его без ответа владельца.
- Факты владельца в группах не используются (FR-20).
- Лимит: 200 фактов на scope. При достижении лимита бот просит удалить старые.

### 6.4 Уровень 4: стили каналов
- Таблица `channels`: `id`, `chat_id` канала, `title`, `style` (текстовое описание: тон, длина, эмодзи, хэштеги, подпись), `example_posts` (до 3 примеров).
- Стиль задаётся командой `/channel add` или редактируется через Mini App.
- Черновики постов используют стиль канала, а не общую память.

### 6.5 Правила памяти
- Чувствительные данные (здоровье, финансы, данные третьих лиц) сохраняются только по явной команде владельца.
- Экспорт памяти: команда `/export` присылает JSON всех таблиц.
- Удаление: `/forget_all` очищает уровни 1–3 для всех чатов после подтверждения.

## 7. Модель данных

Таблицы (SQLite, описываются в `schema.js`):

| Таблица | Поля (основные) |
|---|---|
| `chats` | `chat_id` (PK), `type` (private/group/channel), `model`, `summary`, `mode` (normal/paused), `business_mode` (off/confirm/auto), `ephemeral` (bool), `updated_at` |
| `messages` | `id` (PK), `chat_id`, `role`, `text`, `model`, `tokens`, `created_at` |
| `memories` | `id` (PK), `scope`, `text`, `source`, `created_at` |
| `channels` | `id` (PK), `chat_id`, `title`, `style`, `example_posts` (JSON) |
| `posts` | `id` (PK), `channel_id`, `text`, `file_id`, `status`, `message_id`, `created_at`, `published_at` |
| `business_chats` | `chat_id` (PK), `mode` (off/confirm/auto), `contact_name`, `created_at` |
| `usage` | `date` (PK), `tokens_in`, `tokens_out`, `requests` |
| `journal` | `id` (PK), `type`, `chat_id`, `payload` (JSON, без полного текста переписки), `created_at` |
| `settings` | `key` (PK), `value` |

Связи — обычными колонками (внешних ключей платформа не поддерживает). Целостность проверяется в коде.

Миграции: каждое изменение схемы проходит через `npx tgcloud migrate`. Удаление колонок — через `.deprecated()`.

## 8. Нефункциональные требования

- **NFR-1. Доступ.** Все обработчики сначала проверяют `user_id` и тип чата. Без проверки ничего не выполняется.
- **NFR-2. Безопасность секретов.** Ключ ClaudeHub и CLI-токен не попадают в код и в журнал. Хранятся в секретах платформы или в настройках.
- **NFR-3. Лимиты.** Дневной лимит токенов (по умолчанию 500 000) и лимит запросов в минуту. При превышении бот приостанавливает ответы и сообщает владельцу.
- **NFR-4. Задержка.** Первый токен ответа выводится не позднее 3 секунд после запроса (при доступности ClaudeHub). Если лимит времени выполнения платформы мешает, ответ делится на части или переносится в очередь (см. раздел 12).
- **NFR-5. Надёжность.** Ошибки API логируются. Падение одного обработчика не должно ломать остальные. Повторная обработка одного апдейта (по `update_id`) не создаёт дубликатов сообщений и постов.
- **NFR-6. Журнал.** Журнал пишет действия (кто что сделал, куда, когда), но не полный текст переписки. Полный текст хранится только в `messages` и удаляется командой `/forget_all`.
- **NFR-7. Персональные данные.** Бот хранит данные владельца и собеседников Business. Учитывать 152-ФЗ: хранение и передача данных третьих лиц ограничены и требуют отдельного решения (см. раздел 12).
- **NFR-8. Сопровождение.** Команды `/stop` и `/usage` доступны с телефона. Деплой и тесты проводятся с компьютера через `tgcloud`.
- **NFR-9. Тесты.** Для каждого обработчика есть пример payload в `docs/` или `tests/`, запускается через `npx tgcloud run`.

## 9. Ограничения платформы (из документации)

- Только JavaScript-модули из `tgcloud/`. npm-пакеты недоступны.
- Нет файловой системы, исходящий HTTP только через `fetch` из SDK.
- Ответ `fetch` ограничен 30 МБ.
- Файлы через `InputFile`: до 50 МБ, фото до 10 МБ. Скачивание через `getFileContent`: до 20 МБ.
- База: SQLite, без внешних ключей. Выполнение запросов асинхронное, всегда через `await`.
- Обработчик получает апдейт только если файл обработчика существует и не пустой.
- Лимиты времени выполнения и квоты в документации не указаны (см. раздел 12).

## 10. Используемые возможности Telegram

- Стриминг сообщений (Bot API 9.5): вывод ответа по мере генерации.
- Ephemeral messages (Bot API 10.2): ответы в группах, видимые только автору запроса (FR-19).
- Rich messages (Bot API 10.2): таблицы и списки в постах, если понадобятся.
- Форматирование даты и времени (Bot API 9.5): локальное время в ответах.
- Telegram Business: ответы от имени владельца (раздел 4.4).
- Меню команд и inline-кнопки: выбор модели, подтверждение постов, переделка.
- Mini App (опционально): экран настроек.

Точные имена методов и параметры сверяются с https://core.telegram.org/bots/api перед написанием кода.

## 11. Этапы

**MVP (первая версия):**
- доступ владельца (NFR-1);
- личка: ответы ИИ, стриминг, переключение модели (FR-1–FR-9);
- память уровней 1 и 3, команды `/remember`, `/forget`, `/memory`, `/reset` (FR-10);
- `/stop`, `/resume`, `/usage`, `/help` (FR-29–FR-31);
- посты в один канал: фото + текст → черновик → публикация (FR-21–FR-25, FR-27);
- журнал и лимиты (NFR-3, NFR-6).

**Версия 1:**
- группы: ответ на упоминание, память группы, уведомления владельцу (FR-16–FR-20, FR-33);
- несколько каналов со стилями, уровень 4 памяти (раздел 6.4);
- переделка постов с замечаниями (FR-26);
- сводка истории, уровень 2 (раздел 6.2).

**Версия 2:**
- Business-автоответы (раздел 4.4);
- Mini App для настроек;
- ephemeral-ответы в группах (FR-19);
- экспорт памяти (раздел 6.5).

**Потом:**
- отложенная публикация постов (после уточнения возможностей платформы);
- поиск по своим заметкам по смыслу (внешний API эмбеддингов).

## 12. Открытые вопросы и допущения

1. **ClaudeHub API.** Нужны: эндпоинт, формат запроса и ответа, поддержка стриминга, список моделей, лимиты. Пока считаем API совместимым с форматом OpenAI (`/v1/chat/completions`). Если формат другой, разделы 4.1 и 4.2 пересматриваются.
2. **Лимит времени выполнения платформы.** Неизвестно, сколько можно работать в одном вызове. От этого зависит, нужна ли очередь для длинных ответов.
3. **Квоты и цена Telegram Serverless.** В документации не указаны.
4. **Отложенная публикация.** В документации нет расписания. Нужно уточнить, есть ли cron или аналог. До ответа отложенная публикация не входит в MVP.
5. **Исходящие домены.** Доступен ли ClaudeHub из среды платформы. Проверяется тестом.
6. **Business-режим.** Работает ли обработчик `business_message` в Serverless. Проверяется тестом.
7. **Каналы.** Список каналов (@username) и права админа.
8. **Группы.** Решено (v0.2): три режима, по умолчанию «по запросу».
9. **Персональные данные третьих лиц** в памяти и Business-переписке. Нужно решение, что хранить и сколько.
10. **Язык интерфейса.** Русский. Языки ответов модели определяются запросом.

## 13. Критерии приёмки MVP

- [ ] Бот отвечает владельцу на текст, ответ выводится по частям или целиком.
- [ ] Все остальные пользователи получают отказ и не получают ответов.
- [ ] `/model` меняет модель для текущего чата, выбор сохраняется после перезапуска.
- [ ] `/remember` сохраняет факт, он используется в следующем ответе, `/forget` его удаляет.
- [ ] `/reset` очищает историю чата, факты остаются.
- [ ] `/stop` останавливает ответы, `/resume` возобновляет.
- [ ] Фото + текст → черновик → публикация в канал с сохранением в `posts`.
- [ ] Повторный апдейт не создаёт дубликат поста.
- [ ] `/usage` показывает расход, при превышении лимита бот приостанавливает ответы.
- [ ] Ключи не видны в логах и в коде. **v0.2: ограничение платформы.** В Serverless нет переменных окружения и хранилища секретов, поэтому ключ ClaudeHub при деплое попадает в код бота на серверах Telegram (в репозиторий GitHub не попадает, в логи не пишется). Репозиторий держать приватным, ключ при утечке перевыпустить.
