# Личный ИИ-помощник в Telegram (Serverless)

Бот работает на **Telegram Serverless** — код выполняется на серверах Telegram, свой сервер не нужен. Отвечает через **ClaudeHub API** (OpenAI-совместимый, `https://api.claudehub.fun`). Он помощник владельца «на проценте»: думает о деньгах, сроках и приоритетах, но помогает и со всем остальным — и не льстит. Подробности — в [ТЗ](tz-telegram-bot.md).

## Что умеет

| Возможность | Как пользоваться |
|---|---|
| Ответы ИИ в личке | Просто пишите. Ответ «набегает» живым черновиком (`sendMessageDraft`), кнопка **Стоп** останавливает его |
| Выбор модели | `/model` — список из ClaudeHub по производителям, цены, кеш 24 ч. Модель задаётся отдельно для каждого чата |
| Уровень размышлений | `/think` — выкл / низкий / средний / высокий (бюджет 4 000 / 12 000 / 32 000 токенов на раздумья). Действует в личном чате и в `/code`. Claude идёт через `/v1/messages` (`thinking.budget_tokens`), остальные модели — `reasoning_effort`; если ClaudeHub параметр не принимает, бот сам откатывается и пишет об этом в ответе |
| Длина ответа | В личном чате и в `/code` лимит ответа = максимум модели из каталога ClaudeHub (у Claude 5.x — 128 000). Платишь только за реально сгенерированные токены. В группах, постах и ответах за вас лимит маленький — там важна краткость |
| Память в 4 уровня | последние сообщения → сводка старых → факты (`/remember`, `/memory`, `/forget`, бот сам предлагает кнопкой «Запомнить») → стили каналов |
| Группы | `/group`: **выкл / по запросу / на все**; `/ask`, упоминание и ответ боту работают в режиме «по запросу»; «только автору» (эфемерные ответы, бета) и копии ответов владельцу |
| Ответ за меня в группе | В группе ответьте на сообщение командой `/draft [указание]` → черновик придёт в личку → «Отправить в группу» |
| Ответ за меня в личке | Telegram Business: `/business` → режим на чат: **выкл / с подтверждением / автоматически** |
| Фото и файлы | Пришлите фото/альбом, PDF, Word, Excel, PowerPoint, текст или код — с вопросом в подписи или следом текстом (или кнопка «Разобрать»). До 20 МБ (лимит Telegram для ботов) |
| Посты в каналы | Добавьте бота админом канала → пришлите фото (или альбом) с подписью «пост …» → черновик → **Опубликовать / Переделать / Вручную / Отмена**. Стиль и примеры канала: `/channels` |
| Код в GitHub | `/gh`, `/repo владелец/имя`, `/code задание`: бот читает нужные файлы, пишет изменения и показывает список; по кнопке — **ветка + Pull Request** или сразу в основную ветку. Любые ваши репозитории, **кроме репозитория бота** (он свой код не меняет). Секреты в коде блокируются |
| Репозиторий в чате | «Посмотри репозиторий и сделай пост» (ссылка или `владелец/имя` + «гитхаб»; ветка — «ветка dev») — бот читает **все** текстовые файлы ветки целиком и пишет по фактам из них. Не читает: репозиторий бота, `.env`/ключи и бинарные файлы/`node_modules`. Если не влезает в окно модели — говорит об этом, ничего не отбрасывает молча. Прочитанное остаётся в контексте до `/reset`; под каждым таким ответом кнопки «📦 Убрать репозиторий из контекста» и «🧹 Сбросить весь контекст» |
| Код обычным сообщением | «Создай ветку feature/x в ServGo и добавь чат с ИИ» без `/code` — бот сам понимает, что это задача для кода: находит репозиторий (ссылка, `владелец/имя` или просто имя среди ваших репозиториев), делает предпросмотр с кнопками; ничего не отправляется без нажатия. Модель в чате знает команды бота и не говорит «у меня нет доступа к GitHub» |
| GitHub Actions | `/runs` — последние запуски, кнопки **Run workflow** (для workflow с `workflow_dispatch`, с подтверждением), «что упало», «перезапустить упавшие». Своя ветка и параметры: `/runs deploy.yml ветка env=prod`. Создавать сами workflow-файлы умеет `/code` |
| Контроль | `/usage` (расход и баланс), `/limit`, `/stop` / `/resume`, `/export`, `/reset`, `/forget_all` |
| Защита | Только владелец; чужим — «личный бот» раз в час; защита от дублей апдейтов; лимиты запросов и токенов; журнал действий |

## Развёртывание

Репозиторий уже связан с GitHub Actions: **каждый push в `main` прогоняет тесты и деплоит бота**.

0. *(для `/code`)* секрет **`GH_PAT`** — fine-grained токен GitHub: все репозитории (репозиторий бота лучше исключить), права Contents и Pull requests: Read and write; для GitHub Actions ещё **Actions** (запуск и статусы) и **Workflows** (создание файлов в `.github/workflows`) — тоже Read and write. Без него остальное работает, `/code` выключен.
1. **Секреты Actions** (Settings → Secrets and variables → Actions → *Secrets*): `CLAUDEHUB_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CLI_ACCESS` (токен CLI `tgcloud`) — у вас уже добавлены.
2. **`OWNER_IDS`** (Secrets или Variables — подойдёт любое): ваш Telegram ID, несколько — через запятую. Не знаете ID — задеплойте без неё, напишите боту: он покажет ваш ID и подскажет, что делать.
3. **BotFather:** включите Serverless для бота; для режима «на все сообщения» в группах отключите *Bot Settings → Group Privacy*. Для Business-ответов нужен Telegram Premium: *Настройки → Business → Чат-боты*.
4. Запустите деплой (push в `main` или *Actions → Deploy bot → Run workflow*) и напишите боту `/start`.

Локально: `npm ci && npm test`. Ручной деплой: `CLAUDEHUB_API_KEY=… OWNER_IDS=… TGCLOUD_TOKEN=… npm run deploy`.

## Важно знать

- **Ключ ClaudeHub в коде бота.** В Serverless нет переменных окружения, поэтому `scripts/write-secrets.mjs` перед деплоем кладёт ключ в `tgcloud/lib/secrets.js` — файл в `.gitignore`, в репозиторий и логи не попадает, но на серверах Telegram он лежит внутри кода бота. Сам репозиторий сейчас **публичный**: ключей в нём нет, но виден весь код и промпты — если это неважно, оставьте, иначе переведите в Private (Actions продолжат работать). При подозрении на утечку ключа перевыпустите его и задеплойте заново.
- **Деплой** — `scripts/deploy.mjs`: `tgcloud push --force` (в CI нет локального снимка) → `migrate --safe` → `webhook sync`. Он терпит один известный баг CLI 0.2.0 при записи снимка (код к этому моменту уже на сервере). **Миграции** — только безопасные. Удаление таблиц и колонок — только через `.deprecated()` в `schema.js`.
- **Не проверено вживую.** Код проверен 80+ автотестами на настоящей SQLite и заглушках Telegram/ClaudeHub, но не на самой платформе. Первым делом проверьте после деплоя: (1) ответ в личке и стриминг; (2) кнопку «Стоп» (нужен апдейт `stopped_message_generation`; если платформа не принимает такой обработчик и деплой падает — удалите `tgcloud/handlers/stopped_message_generation.js`, остальное работает); (3) Business и эфемерные ответы (новые функции Bot API — если Telegram их отвергнет, бот откатывается на обычные сообщения); (4) лимит времени одного вызова на длинных ответах — в документации платформы он не указан.
- **Фото альбомом** приходят отдельными апдейтами, поэтому бот просит нажать «Готово» после загрузки всех.
- **Стоимость** в `/usage` — оценка по прайсу моделей; точные списания — в кабинете ClaudeHub.

## Устройство

```
tgcloud/
  schema.js          таблицы (SQLite платформы)
  handlers/*.js      тонкие обёртки над app.handle(): message, callback_query, business_*, my_chat_member, stopped_message_generation
  lib/
    app.js           сборка и маршрутизация, доступ, дубли апдейтов
    chat.js          ответы в личке (стриминг) и в группах
    posts.js         каналы и посты        business.js  ответы от имени владельца
    replies.js       /draft в группах      commands.js  команды и кнопки
    core.js          модели, лимиты, вызов ИИ, сводка   out.js  отправка в Telegram
    llm.js sse.js utf8.js   клиент ClaudeHub (SSE, ретраи, классификация ошибок)
    store.js         весь доступ к БД       deps.js  проводка sdk + секретов
test/                node:test, настоящий Drizzle/SQLite в памяти, подмена `sdk`
```

Модули не обращаются к платформе напрямую: зависимости (`api`, БД, `fetch`, время) приходят через `createApp(D)` — поэтому тесты гоняют тот же код целиком.

## Транспорт: электрички, поезда, междугородние автобусы, самолёты и варианты маршрута (Tutu → Яндекс Расписания)

Для вопросов об электричках/поездах ИИ распознаёт маршрут и дату, но **не генерирует время отправления**. Сначала бот обращается к Tutu MCP. Если Tutu не вернул подтверждённых отправлений, при разрешённом доступе используется официальный API Яндекс Расписаний. Если API не подключён или не дал проверенных результатов, бот сообщает об этом и даёт ссылку на [rasp.yandex.ru](https://rasp.yandex.ru/). Пустая выдача поставщика **не означает**, что рейсов нет.

**Подключение:** владелец добавил и проверил секрет GitHub Actions `YANDEX_API` для Яндекс Расписаний. Приоритет у `YANDEX_API`; резервное имя — `YANDEX_RASP_API_KEY`. Для активации не требуется дополнительная переменная или переключатель. При отсутствии ключа бот остаётся на Tutu и официальных ссылках. Проверка ключа: [HTTP 200](https://github.com/grunvald91/My_ai_assistent/actions/runs/41797331382), [реальный маршрут и остановки](https://github.com/grunvald91/My_ai_assistent/actions/runs/41797635230). Условия использования сервиса: [Яндекс Расписания](https://yandex.ru/legal/timetable_api/ru/); ответственность за соответствие сценарию использования несёт владелец.

Яндекс API требует **коды**, а не названия станций. Для подтверждённых популярных станций есть короткий путь. Для остальных российских городов фоновой задачей скачивается официальный временный справочник (примерно 40 МБ), станция ищется по точному названию и, если есть несколько вариантов в регионах, бот не выбирает один наугад. Справочник не хранится постоянно; масштабирование потребует отдельного разрешённого механизма временного кэширования. Результат API всегда сопровождается надписью «Данные предоставлены сервисом Яндекс.Расписания» и ссылкой на источник. Никакие ключи не выводятся в GitHub Actions или Telegram.

Понимание естественных запросов ИИ поддерживает режимы: `commuter` (электрички), `rail` (поезда), `bus` (междугородние автобусы), `plane` (авиа), `mixed` (разные виды), а также `water` и `helicopter` при наличии соответствующих данных в лицензированном API Яндекс Расписаний. Tutu MCP теперь используется для `search_etrain`, `search_rail`, `search_bus`, `search_avia`, `search_multitransport`. Городские автобусные маршруты Яндекс Расписаниями не покрываются: для них требуется отдельный продукт API Яндекс Карт. Доступность маршрутов зависит от фактической выдачи поставщика; не утверждать, что поддерживается каждый населённый пункт РФ, без живой проверки.

По запросу подробностей Яндекс Расписания может вернуть время отправления и прибытия, длительность, перевозчика и через `thread/` остановки по нитке рейса, если тот же API-ключ принимает запрос и `uid` присутствует в поисковом результате. Запрос деталей — отдельный вызов API, не запускать автоматически для всех рейсов. Не путать квоту «1 000 запросов в сутки» из API Яндекс Карт с квотой API Яндекс Расписаний; последняя требует проверки в кабинете/письме на конкретный ключ.

**Ревью после живой проверки:** в каталоге Яндекса станции электричек могут иметь `transport_type: Поезд` (например, Адлер и Роза Хутор), поэтому разрешение станций для `search_etrain` должно принимать этот тип, сохраняя API-фильтр `suburban` при поиске рейсов. Когда явно запрошены остановки и настроен Яндекс API, приоритет у `search/` + `thread/` в фоновой задаче, с резервом Tutu при сбое. В результате по Адлер → Роза Хутор показываются все 16 остановок, без прежнего обрезания до 12. Секрет `YANDEX_API` приоритетен над старым `YANDEX_RASP_API_KEY` и автоматически подключается при наличии.
